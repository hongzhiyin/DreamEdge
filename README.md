# DreamEdge

DreamEdge 是业务软件开发框架与起点。用户在 DreamEdge 内创建独立工程，通过 AI 开发软件，最终生成可独立安装的 App。当前只推进框架，以 HelloWorld 和通用测试验证能力；已接通本机 macOS 业务 App 导出；正式签名、公证与跨平台发布验收仍在开发。

空白窗口显示 HelloWorld，打开工程后主区域运行已保存源码。右上角按钮展开开发侧栏。打开工程后默认显示 AI 对话，消息独立滚动，输入框固定在底部；Enter 发送，Shift + Enter 换行。顶部齿轮进入独立设置页，分为模型连接、Git 历史、应用与导出和工程管理，返回时保留会话、草稿和运行请求。空白窗口可直接新建或打开工程，新窗口等操作位于设置的工程管理中。

## 使用

需要 Node.js 22.19 或更新版本，以及可执行的 Git。

```bash
npm ci
npm start
```

打开工程并配置模型后，直接描述需求。AI 会自动列目录、搜索和读取源码，提交修改后由框架自动构建，成功后写入工程并刷新页面；无需手动构建、预览或确认保存。构建失败、取消准备或源码冲突时保留当前源码。源码切换临界阶段会完成提交或回退，避免取消造成半次保存。对话中按顺序展示生成回复、工具调用、构建、保存及 Git 提交的状态；每项参数、返回结果与日志可展开，修改差异仍按需查看。若服务返回可展示的思考摘要或模型说明，会显示在对应位置；不会自行补写思考。记录随会话保存，重启可查看。

工程设置的“应用与导出”可保存名称、反向域名 App 标识及数字版本，并选择一个不存在的新目录导出。不同 App 使用不同标识；升级同一 App 保持标识不变。导出生成本机架构的独立 `.app`、ZIP、可再次打开的“工程”目录及固定框架包快照，不复制 API Key、会话、原 Git 历史或业务数据。源码副本使用新工程 UUID；业务 App 数据命名随 App 标识稳定，两个 App 可同时安装和运行。打包复用安装中的 Electron 和固定 electron-builder 库，禁止打包器联网或执行工程脚本，无需另外安装 Node.js/npm；当前为本地 ad-hoc 签名，尚未 Developer ID 公证，不作为公开分发就绪承诺。

业务源码可直接从内置 `@dreamedge/sdk` 导入 `storage`、`callService`，无需把 SDK 添加为 npm 依赖。当前导出的 App 默认只有存储能力，不带开发侧栏；原工程继续在 DreamEdge 中开发。源码或描述在导出准备期间发生变化会拒绝发布，取消停止构建/打包，写入临界阶段完成当前操作；失败保留待核对的部分目标目录，不覆盖已有目录。

TypeScript/TSX、CSS 与依赖需要编译成浏览器可运行的产物，这一步由框架完成。刷新复用成功构建的校验产物；重新打开时使用对应源码的缓存或自动构建。

每个工程有独立 Git 仓库，首次初始化提交当前源码基线。AI 修改默认留在工作区，不自动提交。可以自行使用 Git，也可以在工程设置的“Git 历史”中填写说明后提交；在该设置页勾选“本轮完成后提交工程修改到 Git”后，AI 可生成提交说明，由框架在应用成功后提交工程修改。框架的 Git 操作仅管理 `src`、`.dreamedge/project.json` 和 `.gitignore`，保留其他暂存内容，不自动推送远端。恢复历史内容前需先提交当前修改；恢复不改写 HEAD 历史，而是在工作区产生恢复结果，可再提交。

模型连接保存在各工程的 `.dreamedge/model.json`，含 `schemaVersion: 1`、`apiKey`、`model`、`baseUrl`，可直接编辑。侧栏提供 DeepSeek/OpenAI 预设和“重新读取文件”。DeepSeek 官方地址为 `https://api.deepseek.com`、模型可用 `deepseek-flash`；OpenAI 地址为 `https://api.openai.com/v1`。当前通过 pi 原生 Responses 适配器连接，服务需支持 SSE 与函数工具参数。

配置文件为可编辑文本，保存时加入工程 `.gitignore`，位于源码之外，不进入模型上下文、构建和 Git 自动提交。界面不返回 Key 原值。请求会发送 AI 按需读取的源码和会话记录，测试和对话可能产生模型服务费用。新请求重新读取配置文件，运行请求固定开始时的连接；文件修订校验防止旧表单覆盖手动编辑。

会话与执行使用 pi-agent-core 的 Agent 类，协议、流式消息和推理签名使用 pi-ai 原生适配器。DreamEdge 提供受控工程工具、结构化修改提交、构建、事务保存和 Git 边界。AI 的依赖查询和声明通过 pi 工具扩展点执行，查询只访问公共 npm 元数据，声明不会立即安装或写入工程。每轮最多 12 次模型请求、48 次工具调用、64 个查阅文件及 128 KB 源码，最长 5 分钟；临时事务目录用于中断恢复，工程历史只使用 Git，不再维护另一套版本快照。

一份 DreamEdge 可同时打开多个独立工程窗口，源码、会话、连接、运行内容和业务数据分别隔离。退出后恢复窗口和工程。Git 恢复只作用于源码及工程描述，模型配置、会话与业务数据不回退。

## 验证与当前限制

`npm test`、`npm run build`、`npm run test:desktop`、`npm run test:packaged` 验证框架与 App。`npm run test:framework` 使用两个临时独立 App 验证框架包和数据隔离。`npm run framework:pack` 生成内部验证包，尚未发布 npm；已验证源环境及已安装 App 的 macOS 导出，跨平台导出仍待完成。

构建使用固定可信编译器与受控 npm 浏览器依赖，准确版本和归档完整性锁定在工程描述中。已有完整缓存可离线重建；不运行安装脚本，不支持私有/Git/本地依赖、原生平台包或任意生成 Node.js 服务。AI 可改写或删除已读取源码、创建新文件，并查询 npm 版本、声明完整直接依赖列表；依赖新增、升级、移除和源码变更统一构建后自动应用。仅修改依赖也会构建，仍被源码引用的依赖不能直接移除。差异记录显示文件删除与依赖变化，Git 提交和恢复涵盖源码及依赖锁定。模型会话中断后重新发送，完整跨进程工具续跑、更多协议及逐字回复界面尚未完成；思考摘要和模型说明目前按完整文本段更新。

手机原型使用 `npm run ios:sync` 和 `npm run ios:open`，需要完整 Xcode，最低 iOS 16；手机内部 AI 开发尚未实现。
