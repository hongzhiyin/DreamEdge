# 业务上下文与 MCP 授权交接

当前阅读器已增加免确认打开、翻页、跳转和缩放，见 [免确认会话与普通阅读操作](reader-navigation.md)（2026-10-18）。下文保留最初只读交接阶段的实现说明。

状态：已实现，只读范围。日期：2026-10-17。协议：`ai-session-launch/v1` 的可选 `mcp` 声明；当前交接支持 stdio。没有提供声明的旧请求继续创建纯文字会话。

## 接口与职责

业务应用从自身已认证的窗口连接取得不透明的 `context.window/resource`，由原生层附加自己的 MCP 启动入口。AI 宿主只理解传输、读取工具清单和授权范围，不解释书籍、页码等字段。

```json
{
  "mcp": {
    "transport": {"type":"stdio","command":"/absolute/provider-cli","args":["mcp","--scope","opaque-context"]},
    "scope":"当前窗口内选定资源的只读内容",
    "readTools":["read_context","read_content"]
  }
}
```

此段附加到现有 open-session 请求。`readTools` 最多 16 项，stdio 使用绝对路径和参数数组；不接受 shell 字符串、环境变量凭据引用、HTTP 地址或秘密值。MCP 名称与参数由提供方决定，DreamEdge 没有阅读器名称或工具名分支。

首次确认展示应用、模型与服务地址、读取范围、工具名称、可执行文件和参数。用户批准后才启动 MCP 进程。宿主使用 Pi Client／StdioTransport 发现能力，校验允许清单与 schema，保存配置身份、定义摘要、模型目的地和读取授权。服务端的 readOnlyHint 仅为描述，不能获得自动执行权限。

相同应用、窗口、资源、入口、能力与模型目的地下恢复授权；新书籍或新窗口是新范围，需要确认。模型目的地或能力定义变化时重新确认。已有内容不属于新授权时创建新的绑定会话，原会话保留并撤销旧页面访问，避免混用历史。

## 执行与持久化

- 专用 launch-mcp.sqlite 登记库与普通 mcp.json 隔离。读取会话不加载普通配置、本机文件工具或写工具。
- externalTools 标记随会话保存。launch.sqlite 保存范围授权；缺失、撤销或目的地不一致时停止执行，不能回退到普通工具。
- Pi 继续负责 Agent 循环与协议传输。工具快照保存 readGrantDigest；每次读取检查授权、配置与 schema、当前运行和已落盘的执行意图。审批为 never 只用于已明确批准的读取清单，普通 MCP 工具仍逐次审批。
- 读取返回后再次检查取消信号和授权。结果、来源、参数与执行状态按现有流程保存；后续请求重新检查历史读取授权。
- open-session 只交接标识并建立连接，不读取正文、不调用模型。用户提问后模型按需调用上下文工具和内容工具，不预先上传整本书。
- revoke 撤销页面、范围授权与连接，并停止该应用正在进行的运行；历史保留，后续推理不能继续使用失效授权的数据。

## 阅读器实现

“外部对话”按钮自动启用本地桥接，等待当前页就绪，通过已认证 WebSocket 请求上下文。服务端返回自己的窗口 clientId、书籍 ID 和版本；原生层从自身应用包取得 MCP 入口，附加 `mcp --window <id> --book <id>`。

该 scoped MCP 实例仅暴露：

| 工具 | 内容 |
| --- | --- |
| rg_context_get | 当前书籍、物理页码、选段、问题草稿及 contextVersion |
| rg_page_read | 绑定书籍中一个明确物理页的可提取文字；需要上一步返回的 contextVersion |

模型不能传入或覆盖窗口和书籍 ID。服务端每次按固定窗口查找唯一连接、核对书籍、验证页面版本；读取期间发生切换则丢弃结果。关闭窗口、切书、过期版本和未知写操作均拒绝，不选择其他窗口作为替代。现有完整 MCP 模式保留，限定实例不会暴露完整模式的其他工具。

读页不改变阅读进度，不写引用或笔记。本阶段没有 OCR、截图、视频、整本书批量读取和写操作交接；扫描 PDF 可能没有可提取文字。

## 使用与恢复

使用本阶段两个验收包。阅读器首次选择新的 ai-entry.json；点击“外部对话”后确认当前书籍读取范围，即可询问当前页或选段。无需另行粘贴 MCP JSON 或点“连接本地服务”。同一范围重开面板或重启 DreamEdge 可恢复授权与历史；切换书籍会打开另一个绑定会话。

入口或权限失效时从阅读器“重连”。阅读器进程完全退出后的稳定窗口身份恢复、后台断线后的主动重新拉起尚未加入。首次导入 AI 执行入口与 AI 侧内容授权仍是两个职责不同的确认步骤。

同账户本地互操作沿用既有 Unix socket 权限边界；不宣称已验证签名应用身份。提供方必须在自己的服务端落实 scope，宿主不能只凭工具的只读注解信任任意服务器。

## 验证与兼容

依赖保持 Pi 1.1.0，复用现有 McpConnectionRegistry、McpConnectionManager、createMcpRunPreparation、PiRuntime 和工具落盘流程，没有另写 MCP Client 或 Agent 循环。DSH 的插件生命周期不承担业务窗口约束，本阶段未引入新 DSH 运行时。阅读器复用原有 MCP SDK、BridgeHub 与 PDF 读取代码。

验收记录见 `docs/validation/business-context-2026-10-17.json` 与 `business-context-live-2026-10-17.json`。自动测试使用隔离配置与合成 PDF；人工验收只在用户确认后记录。

新授权摘要及外部会话字段为持久化扩展，旧版不能保证理解新增的只读 MCP 快照。回退时需使用升级前的数据备份或独立旧数据目录，不能让旧版本直接加载已包含新快照的数据库。本次验收使用隔离数据，未替换旧包或修改日常数据。
